# EB521 V1.2 云台与 UART

R2 默认 AP 配置启用 `CONFIG_MYBOT_GIMBAL`，通过 UART2 连接 V1.2 协议的 EB521 底板。
首次使用时，上板自动请求充电并开始回中。之后上电会恢复用户保存的选择。语音和串口调试通过同一个 UART 任务提交绝对角度。底板可以稍后接入。

## 接线与串口

| 信号 | BK7259 | EB521 |
| --- | --- | --- |
| TX | GPIO2 / UART2_TX | RX |
| RX | GPIO3 / UART2_RX | TX |
| GND | GND | GND |

UART 参数为 115200、8 数据位、无校验、1 停止位、无流控。GPIO3 使用内部上拉保持空闲高电平。
联调时可在 CN1 的 2 脚观察请求、3 脚观察应答，均以 4 脚 GND 为参考。

## 协议

帧格式：

```text
03 + command + BE16(payload_length) + payload + LE16(Modbus-CRC16)
```

CRC 初值为 `FFFF`，多项式为 `A001`，覆盖帧头到 payload 末尾。单帧总长不超过
200 字节。

- `0x61` 下发左右、上下两轴绝对角度。角度以 0.1° 为单位，向右和向下为正。
  R2 限位为左右 ±80°、上仰 20°、下俯 10°。速度字段范围为 1～1000 pps，
  底板按 `floor(5000 / pps)` 毫秒每度执行。上板按每轴相邻目标的角度差和采样间隔
  选择能按时到达的最低 PPS。例如 3° 走 40 ms，使用 358 pps，协议预计耗时 39 ms。
- `E1/00` 表示开始转动，后续 `E1/06` 回显目标坐标。`E1/04` 表示已经到位。
  `E1/01` 表示开机演示未结束，`E1/02` 表示速度非法。底板对新接收的有效绝对目标立即执行覆盖。
- `0x66/01` 请求或续期充电，周期为 1000 ms。`0x66/00` 停止充电。`E6/00`
  表示底板已执行请求，`E6/02` 表示控制字节非法。有效续期间隔达到 3000 ms 时，
  底板关闭充电。

## 上电、热插拔与回中

启用舵机控制时，上电后发送双轴绝对目标 `(0,0)`，两轴速度均为 1000 pps。每秒再尝试一次，直到收到
可归属于回中的 `E1/04`，或坐标为 `(0,0)` 的 `E1/06`。`E1/00` 只确认开始，
充电心跳的 `E6` 只确认充电请求。回中期间丢弃普通动作，底板缺席时语音和屏幕可以正常启动。
舵机控制保存为关闭后，下次开机不发送运动帧。

已确认中位后，按轨迹的当前时间发送最新的绝对目标。切换动作时从上次下发角度缓动衔接，大角度移动会延长过渡。
开心摆动有幅度渐入和渐出，惊讶动作从 25° 回正的缓动约为 605 ms，随后进入回中确认。中间帧漏应答时继续后续采样。
挂断会清除未发送的动作，并以同样的速度和周期回中直到确认。底板返回开机演示、连续约 3.25 秒收不到有效运动或充电应答，
或持续发送运动约 1 秒都没有运动应答时，上板清除旧位置和旧动作，再次确认中位。重新就绪后按当前阶段执行。
协议没有独立的拔插通知，极短的断开可能落在两次通信之间。

## 设置菜单

两个选项独立保存，按钮文字显示下一次点击会执行的操作。

- **关闭舵机控制**会丢弃待发动作，发送一条 `0x61` 双轴绝对回中指令，目标为 `(0,0)`，两轴速度均为 1000 pps。无应答时也只发送一次。再次点击**开启舵机控制**后，上板先确认回中，然后跟随当前对话阶段。
- **关闭供电请求**会把每秒的 `0x66` 控制字节切到 `00`，请求底板停止给上板充电。再次点击**开启供电请求**后，控制字节恢复为 `01`，每秒续期。舵机运动和上板语音仍可使用。
- 菜单显示上板的供电许可。实际充电电流可通过底板指示或电流表核验。恢复出厂后两项均开启。

设置变更先在本次运行生效，再写入 EasyFlash。菜单显示“保存失败，点击重试”时，轻触提示可重新保存。上电读取到无效记录时，两项都关闭。EasyFlash 将缺失的记录报告为首次使用；若底层已丢弃损坏的记录，也会使用首次启动的默认值。

## CLI

在日志控制台可执行以下命令。正常使用时短按 GPIO47 开聊即可。

```text
ap_cmd gimbal_cmd
ap_cmd gimbal_scene happy
ap_cmd gimbal_dialogue start
ap_cmd gimbal_dialogue listening
ap_cmd gimbal_dialogue thinking
ap_cmd gimbal_dialogue speaking
ap_cmd gimbal_dialogue end
ap_cmd gimbal_charge off
ap_cmd gimbal_charge on
ap_cmd gimbal_probe
```

- `gimbal_cmd` 循环选择四个绝对目标：向左 30°、向下 10°、向上 20°、向右 10°。
- `gimbal_scene [happy|sad|angry|surprised]` 提交一组动作，不带参数时依次循环。等待回中时显示 `not ready`。
- `gimbal_dialogue start|listening|thinking|speaking|neutral|end` 调用语音对话使用的阶段接口，仅驱动云台。
  回答摆幅取自实际播放的声音，静音时回中。CLI 和语音共用运动入口，新的运动请求可以覆盖旧请求。
- `gimbal_charge off|on` 和设置菜单共用供电许可，并保存到下次启动。启用后每秒发送充电控制帧；
  关闭时停止续期并发送停充控制帧。重启前尝试确认停充，底板断链后按协议在最后一次有效续期的 3 秒后停充。
- `gimbal_probe` 是可选的 UART 诊断。有效的 `E6/02` 表示底板收到了诊断帧。

## 对话联动

| 事件 | 屏幕与云台表现 |
| --- | --- |
| 会话建立 | 屏幕短暂显示惊讶，云台做一次小幅快摆并回正。只有已确认中位才播放开场动作。 |
| 聆听 | 显示聆听表情。连续聆听约 3.5 秒后，云台用俯仰轴轻点两次，一组约 1.12 秒，角度约 ±3°。短句结束即取消待执行的点头。 |
| 思考 | 显示思考表情，云台约用 700 ms 缓缓转向 15°。同一阶段持续 3 秒后，屏幕转为处理中，云台平滑转入小幅慢摆。 |
| 回答 | 显示微笑的中性表情，云台随实际写入扬声器的语音能量摆动，最大约 ±6°。静音或播放停止后收回中位。 |
| 挂断、断网或进入配网 | 取消待执行的对话动作并回中，收到中位确认后重新开放控制。 |

聆听、思考和回答以 SDK 上报的阶段为准。相同阶段的重复通知保留原有计时。

## 测试

```bash
bash projects/mybot/tests/gimbal/run.sh
ASAN_OPTIONS=detect_leaks=0 GIMBAL_TEST_SANITIZERS=1 bash projects/mybot/tests/gimbal/run.sh
```

实板验收从上板独立上电开始，随后接入底板，确认自动回中和正常开聊。对话中拔下并重新接入底板，
检查恢复后的第一类运动请求为回中，并验证挂断后丢一帧应答仍能确认中位。用电流表或底板指示核验
默认充电、显式停充，以及断开 UART 后的 3 秒停充时序。
